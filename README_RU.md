# Yandex Disk Sync для Obsidian

Плагин для синхронизации заметок Obsidian с Яндекс Диском. Позволяет автоматически синхронизировать хранилище между несколькими устройствами через облачное хранилище Яндекса.

## Обновление до 2.0.0-beta.1

Версия 2.0.0-beta.1 использует новый индекс синхронизации и не может одновременно
работать с версией 1.1. Закройте Obsidian на остальных устройствах, создайте
резервную копию vault и обновите плагин везде. На устройстве с наиболее полными
данными выполните **Принудительная синхронизация → Локальное → Удалённое** с
созданием бэкапа. На остальных устройствах выполните **Удалённое → Локальное**,
также с бэкапом.

Не запускайте версию 1.1 после перехода: она может заменить индекс v3 и вернуть
удалённые файлы. Если это произошло, отключите синхронизацию везде, выберите
наиболее полную локальную копию, проверьте backup/conflict-копии и повторите
принудительную синхронизацию из версии 2.0.0-beta.1.

>

> **Требования к аккаунту**
> Для загрузки файлов размером более 2 ГБ требуется активный тариф Яндекс 360. Бесплатная версия имеет ограничения на размер файлов и общий объём хранилища.
>
> **Конфиденциальность**
> Плагин не собирает и не передаёт разработчику ваши данные, содержимое файлов или метаданные. Все операции выполняются локально на вашем устройстве через официальный API Яндекс Диска.

## Возможности

- **Реал-тайм синхронизация** — автоматическая загрузка изменённых файлов при сохранении
- **Периодическая полная синхронизация** — проверка и синхронизация всех файлов по таймеру
- **Двусторонняя синхронизация** — изменения с любого устройства синхронизируются на все остальные
- **Разрешение конфликтов** — причинные правила по SHA-256, server mtime и
  tombstone с сохранением вытесняемой локальной версии
- **Синхронизация удалений** — удалённые файлы удаляются на всех устройствах
- **Гибкие фильтры** — настраиваемые паттерны включения/исключения файлов
- **Поддержка нескольких устройств** — работа по одному токену на разных устройствах
- **Система бекапов** — создание ZIP-архивов хранилища на Яндекс Диске
- **Принудительная синхронизация** — безусловная однонаправленная перезапись (локальное→удалённое или удалённое→локальное) для восстановления или ручной ресинхронизации
- **Сквозное шифрование** — AES-256-GCM шифрование содержимого файлов и имён с выводом ключа через PBKDF2

## Установка

### Вручную

1. Скачайте `main.js`, `manifest.json` и `styles.css` из [последнего релиза](../../releases)
2. Создайте папку `yandex-disk-sync` в `<Vault>/.obsidian/plugins/`
3. Скопируйте скачанные файлы в созданную папку
4. Перезапустите Obsidian
5. Включите плагин в **Настройки → Сторонние плагины**

### Через BRAT (для бета-тестирования)

1. Установите плагин [BRAT](https://github.com/TfTHacker/obsidian42-brat)
2. Добавьте репозиторий через BRAT
3. Выполните "Check for updates in BRAT"

## Настройка

### Получение OAuth-токена

> **⚠️ Важно**
> Для загрузки файлов размером более 2 ГБ требуется активный тариф Яндекс 360. Бесплатная версия Яндекс Диска предоставляет только 5 ГБ хранилища.

1. Перейдите на [Яндекс OAuth](https://oauth.yandex.ru/)
2. Создайте приложение с правами `cloud_api:disk.app_folder` (рекомендуется) или `cloud_api:disk.read` + `cloud_api:disk.write`
3. Получите OAuth-токен
4. Вставьте токен в настройки плагина

## Использование

### Первый запуск

При первом запуске плагин проверяет наличие файлов локально и на Яндекс Диске:

- **Если локальное хранилище пусто, а на диске есть файлы** — файлы будут скачаны
- **Если диск пуст, а локально есть файлы** — файлы будут загружены
- **Если файлы есть в обоих местах** — плагин выполнит двустороннюю слияющую синхронизацию

> **⚠️ Рекомендация**
> Перед первой синхронизацией создайте ручной бекап вашего хранилища. При работе с облачными данными всегда есть риск потери информации.

### Работа на нескольких устройствах

1. Настройте плагин на первом устройстве и выполните первичную синхронизацию
2. На втором устройстве установите плагин с тем же токеном и путём
3. Плагин автоматически скачает файлы с Яндекс Диска

> **⚠️ Важно**
> Используйте один и тот же токен на всех устройствах. При смене токена потребуется перенастроить синхронизацию на всех устройствах.

### Разрешение конфликтов

Локальные изменения определяются по SHA-256, удалённые — по server mtime и
серверному fingerprint. Если изменились обе стороны, плагин создаёт
conflict-копию. Точечное удаление побеждает конкурентное изменение, но
вытесняемое локальное содержимое сначала сохраняется в backup. Новый или
изменённый файл внутри конкурентно удалённой папки выживает.

> **⚠️ Предупреждение**
> Удаления распространяются на все устройства. Для важных vault храните
> независимый backup, особенно перед Force sync.

### Система бекапов

Плагин включает встроенную систему бекапов для создания ZIP-архивов вашего хранилища:

- **Создание бекапов**: Настройки плагина → Секция "Бекап" → Кнопка "Сделать бекап"
- **Место хранения**: Бекапы сохраняются в папку `.backup` на Яндекс Диске
- **Формат**: `backup_YYYY-MM-DD_HH-MM-SS.zip`
- **Содержимое**: Все файлы, подлежащие синхронизации согласно фильтрам
- **Синхронизация**: Время последнего бекапа синхронизируется между устройствами

**Примечание**: Папка `.backup` защищена и исключена из операций синхронизации.

### Принудительная синхронизация

Плагин включает функцию **Force Sync** для случаев, когда обычная двусторонняя синхронизация недостаточна:

- **Синхр. локальное → удалённое**: перезаписывает ВСЕ файлы на Яндекс Диске локальными версиями. Файлы, отсутствующие локально, удаляются с диска.
- **Синхр. удалённое → локальное**: перезаписывает ВСЕ локальные файлы версиями с Яндекс Диска. Файлы, отсутствующие на диске, удаляются локально.

Принудительная синхронизация игнорирует временные метки, хеши файлов и механизм разрешения конфликтов — она создаёт точную копию в выбранном направлении.

> **⚠️ Предупреждение**
> Принудительная синхронизация деструктивна. Перезаписываемая сторона полностью
> заменяется. Плагин разрешает продолжить только после успешного создания
> бекапа.
>
> **Где найти**: Настройки → Секция "Принудительная синхронизация".

### Шифрование

Плагин поддерживает сквозное шифрование содержимого файлов и имён с использованием **AES-256-GCM** и выводом ключа через **PBKDF2** (100k итераций, HMAC-SHA256):

Во время включения, выключения или смены пароля остальные устройства
блокируют обычную синхронизацию. Если инициирующее устройство утрачено,
восстановление выполняется только через **Принудительная синхронизация →
Локальное → Удалённое** на устройстве с проверенной полной копией и после
создания backup.

- **Шифрование содержимого**: каждый файл получает случайный 12-байтный IV, что гарантирует уникальный шифротекст даже для одинаковых файлов
- **Шифрование имён**: детерминированный IV на основе пути файла через SHA-256 — зашифрованные имена стабильны между устройствами и сессиями
- **Ключ**: выводится из вашего пароля + случайной 16-байтной соли — мастер-ключ никогда не покидает ваше устройство
- **Несколько устройств**: соль хранится в общем файле `.obsidian-encrypt.json` на Яндекс Диске (raw, без шифрования). При включении шифрования на новом устройстве плагин автоматически определяет зашифрованные данные, запрашивает пароль и проверяет его корректность

**Как включить**:

1. Перейдите в **Настройки → Секция "Шифрование"**
2. Нажмите на тоггл шифрования
3. Выберите, создавать ли бекап перед включением
4. Введите и подтвердите пароль
5. Дождитесь завершения первичной синхронизации (все файлы будут перезагружены в зашифрованном виде)

**Восстановление пароля**: Пароль НЕ восстанавливается. Если вы потеряете пароль при включённом шифровании, ваши данные на Яндекс Диске станут навсегда недоступны. Храните пароль в надёжном месте (например, в менеджере паролей).

**Хранение пароля**: Пароль хранится в `data.json` (конфиг плагина Obsidian) в открытом виде. Он никогда не отправляется на Яндекс или третьим лицам.

> **⚠️ Предупреждение**
> Включение шифрования повторно загрузит все файлы в зашифрованном виде. Старый
> plaintext-набор остаётся авторитетным до commit canonical index и затем
> удаляется только guarded-cleanup при совпадении fingerprint. Полученные
> зашифрованные данные невозможно прочитать без пароля.

```bash
npm install
```

- OAuth-токен хранится локально в зашифрованном виде в настройках Obsidian
- Токен не логируется и не передаётся третьим лицам
