# Yandex Disk Sync для Obsidian

[English](README.md)

Синхронизируйте хранилище Obsidian между компьютерами, телефонами и планшетами
через Яндекс Диск. Плагин работает на Windows, macOS, Linux, iOS и Android.

> [!WARNING]
> **Плагин не гарантирует сохранность ваших данных. Вы используете его на свой
> страх и риск. Автор не несёт ответственности за сохранность ваших данных.**
> Ошибки или сбои синхронизации могут привести к потере данных.
> Перед использованием сделайте независимую резервную копию важных файлов.
> Удаления распространяются на другие устройства, а принудительная синхронизация
> заменяет файлы назначения. Синхронизация не заменяет резервное копирование.

**Конфиденциальность:** Плагин не собирает метрики, аналитику использования или
телеметрию. Он не передаёт автору ваши файлы, OAuth-токен или пароль шифрования.
Автор не имеет доступа к вашему хранилищу через плагин.

Язык интерфейса выбирается по настройкам Obsidian. Другой язык можно выбрать
в настройках плагина.

## Возможности

- Двусторонняя синхронизация, автоматическая загрузка изменений и полная проверка по таймеру.
- Синхронизация удалений с сохранением вытесняемых локальных данных и обработкой конфликтов.
- Фильтры включения и исключения файлов, синхронизация настроек Obsidian по выбору.
- Резервные ZIP-архивы на Яндекс Диске.
- Принудительная синхронизация с выбранного устройства или из облака.
- Сквозное шифрование содержимого и имён файлов по выбору.

## Установка

### Вручную

1. Скачайте `main.js`, `manifest.json` и `styles.css` из
   [последнего релиза](https://github.com/Ivansushkin/obsidian-yandex-disk-sync/releases/latest).
2. Создайте папку `<Vault>/.obsidian/plugins/yandex-disk-sync/` в своём хранилище.
3. Скопируйте в неё три скачанных файла.
4. Перезапустите Obsidian.
5. Включите **Yandex Disk Sync** в **Настройки → Сторонние плагины**.

### Предварительные сборки через BRAT

Установите [BRAT](https://github.com/TfTHacker/obsidian42-brat) и добавьте репозиторий
`Ivansushkin/obsidian-yandex-disk-sync`. Проверяйте обновления через BRAT.

## Первое подключение

1. Сделайте резервную копию локального хранилища.
2. Получите токен через [Яндекс OAuth](https://oauth.yandex.ru/): создайте приложение
   с необходимыми правами чтения и записи Яндекс Диска и получите OAuth-токен.
3. Откройте настройки плагина и вставьте токен.
4. Выберите отдельную папку на Яндекс Диске, например `obsidian-sync/my-vault`.
   Для каждого хранилища используйте свою удалённую папку.
5. Проверьте фильтры синхронизации и решите, нужно ли переносить настройки Obsidian.
6. Запустите полную синхронизацию и дождитесь её завершения перед подключением другого устройства.

После смены токена или удалённой папки выполните успешную полную синхронизацию
вручную, чтобы включить автоматическую синхронизацию для этого подключения.

Если удалённая папка пуста, локальные файлы загружаются на Диск. Если локальное
хранилище пусто, файлы скачиваются из облака. При подключении нового устройства
к существующим облачным данным сначала принимаются облачные версии. Отличающиеся
локальные версии сохраняются в `.obsidian/plugins/yandex-disk-sync/overwritten/`;
файлы, которые есть только на устройстве, сохраняются и загружаются после
начального получения данных.

На другом устройстве установите плагин, укажите тот же OAuth-токен и удалённую
папку, затем запустите полную синхронизацию. Для зашифрованных данных введите тот
же пароль шифрования, когда плагин его запросит.

Используйте одинаковую версию плагина на всех устройствах. Старые и новые сборки
не должны одновременно работать с одной удалённой папкой. Перед обновлением
существующей настройки прочитайте инструкции к релизу и сохраните резервную копию
хранилища.

## Повседневная работа

Включите синхронизацию при изменении файлов, чтобы локальные правки автоматически
отправлялись на Диск. Периодическая полная синхронизация также проверяет изменения
с других устройств. Полную синхронизацию можно запустить вручную в любой момент.

| Настройка                      | Для чего нужна                                                    |
| ------------------------------ | ----------------------------------------------------------------- |
| Синхронизация при изменениях   | Автоматически отправлять локальные правки.                        |
| Интервал полной синхронизации  | Задать частоту проверки всего хранилища; ноль — только вручную.   |
| Задержка синхронизации         | Выждать паузу после редактирования перед загрузкой.               |
| Параллельные операции          | Настроить число одновременных передач файлов и чтений метаданных. |
| Фильтры включения и исключения | Выбрать файлы для синхронизации с помощью glob-шаблонов.          |
| Синхронизация папки настроек   | Переносить настройки Obsidian между устройствами.                 |

Данные самого плагина и удалённая папка `.backup` защищены и исключены из
синхронизации.

В палитре команд доступны полная синхронизация, пауза и возобновление, просмотр
статуса и создание резервной копии. Нажмите на индикатор `YD`, чтобы увидеть
прогресс, время последней успешной синхронизации и ошибки. Покой индикатора
не означает, что изменения с другого устройства уже получены.

### Конфликты и удаления

Если файл изменён с обеих сторон, плагин сохраняет конфликтную копию. При обычной
синхронизации удаление файла имеет приоритет над одновременным редактированием;
вытесняемые локальные данные сохраняются перед заменой или удалением.
Просматривайте конфликтные и защитные копии, прежде чем удалять их.

Подробнее: [обработка конфликтов](docs/CONFLICTS.md).

## Резервные копии

Создайте ZIP-архив в разделе резервного копирования в настройках плагина или через
палитру команд. В архив входят файлы, выбранные фильтрами синхронизации. Архивы
хранятся в `.backup` внутри удалённой папки, а их список доступен с разных устройств.

Для зашифрованного архива нужен пароль, действовавший при его создании. При
скачивании через плагин архив расшифровывается в обычный ZIP. Храните независимые
копии важных архивов за пределами синхронизируемого хранилища.

Подробнее: [резервное копирование](docs/BACKUP.md).

## Принудительная синхронизация

Используйте Force, когда нужно заменить данные на одной стороне данными с другой:

- **Устройство → Диск:** заменить выбранные облачные файлы файлами с этого устройства.
- **Диск → устройство:** заменить выбранные локальные файлы файлами с Яндекс Диска.

Оба направления учитывают фильтры включения и исключения, переключатель
синхронизации настроек Obsidian и защищённые пути. Исключённые файлы и работающий
плагин синхронизации сохраняются.

> **Force заменяет файлы назначения**
>
> Проверьте направление и источник перед подтверждением. В диалоге можно выбрать
> создание архива; по умолчанию оно выключено. Без архива Force не создаёт
> защитных или конфликтных копий. Успешно прочитанный пустой источник очищает
> выбранные файлы назначения.

Ошибка чтения источника блокирует замену. После частичного сбоя обычная полная
синхронизация повторяет оставшиеся действия. Останавливать другие устройства
не обязательно, но их поздние запросы могут повлиять на результат. После замены
настроек Obsidian перезапустите приложение.

Подробнее: [принудительная синхронизация](docs/FORCE_SYNC.md).

## Шифрование

Сквозное шифрование защищает содержимое и имена файлов на Яндекс Диске. Локальные
файлы остаются читаемыми в Obsidian. Для содержимого используется AES-256-GCM,
для имён — AES-SIV.

Чтобы включить шифрование, откройте соответствующий раздел настроек плагина,
введите и подтвердите пароль, затем выберите, создавать ли архив перед
продолжением. Сохраните пароль в менеджере паролей: восстановить его нельзя,
а без него зашифрованные облачные данные недоступны.

Включение, выключение и смена пароля шифрования используют локальные файлы
запускающего устройства как эталон в пределах фильтров синхронизации. Файлы только
в облаке и старые правки с устройств, работавших без сети, не добавляются к этому
эталону. Заранее сохраните нужные копии отдельно и не редактируйте хранилище
ни на одном устройстве до завершения операции.

Подробнее: [шифрование](docs/E2E_ENCRYPTION.md).

## Безопасность и ограничения

- OAuth-токен и пароль шифрования хранятся открыто в локальных данных плагина.
  Не передавайте эту папку и диагностику, содержащую секреты.
- Плагин отправляет синхронизируемые данные на Яндекс Диск и не собирает телеметрию.
  Пароль шифрования не отправляется на Яндекс Диск.
- Удаление данных плагина не отзывает OAuth-токен. Отзывайте ненужные токены
  через Яндекс OAuth.
- Обычная синхронизация не переносит пустые папки, Force переносит.
  Символические ссылки и специальные атрибуты файлов не синхронизируются.
- Объём хранилища, ограничения размера файлов и частоты запросов задаёт Яндекс Диск.
- При создании ZIP файлы архива находятся в памяти; для большого хранилища памяти
  устройства может не хватить.

Технические подробности и инструкции для разработки — в
[путеводителе по документации](docs/README.md).
