# Yandex Disk Sync для Obsidian

Плагин для синхронизации заметок Obsidian с Яндекс Диском. Позволяет автоматически синхронизировать хранилище между несколькими устройствами через облачное хранилище Яндекса.

**Языки интерфейса:** English · Русский · Қазақша · Беларуская · O‘zbekcha.
По умолчанию плагин следует языку Obsidian. В начале настроек можно выбрать
язык вручную — он применяется сразу.

Изменения подключения и состава синхронизации применяются после согласованного
локального сохранения. Активные операции и незавершённый recovery могут блокировать
изменения. Архитектура, сценарии и проверки собраны в [путеводителе](docs/README.md).

## Подключение

Выберите папку на Диске, настройте OAuth и нажмите **Синхронизировать**. После
сохранения нового токена или папки автоматическая синхронизация ждёт успешного
ручного запуска, в том числе после перезапуска Obsidian. Подключения из 2.0.0
сохраняют автоматический старт до изменения этих настроек. Поле токена скрывает
ввод; credentials по-прежнему хранятся локально.

Пока настройки открыты, одно уведомление повторяет статус синхронизации и исчезает
в покое или при закрытии настроек. Кнопки логов позволяют **копировать последние
4000 символов** после маскировки, **открыть файл** и **очистить его** с подтверждением.
Число символов отображается в подсказке при наведении или фокусе. Копирование и
открытие доступны также из плашки. Внешнее открытие зависит от поддержки Obsidian;
встроенный просмотрщик удалён.

## Обновление с 1.1.0 до 2.0.0

Версия 2.0.0 поддерживает миграцию только с plaintext stable 1.0.0 и 1.1.0.
Локальные settings и baseline сразу сохраняются в current `plugin-data` после
инициализации installation ID, до запуска автоматизации. Откат формата на 1.1
не поддерживается. Ошибка сохранения блокирует синхронизацию.
Plaintext canonical stable `version: 1`/`version: 2` требует явного Force.
Force заменяет выбранные файлы назначения и предлагает необязательный архив,
выключенный по умолчанию. Старые canonical/fingerprints назначения не проверяются
для выбора победителя; source читается до очистки. Другие устройства принимают
новый epoch обычным full с прежним решением об offline-правках.
Остановка остальных устройств не является условием Force, но поздние запросы
старых клиентов могут изменить результат. Resume не снимает ordinary startup-блокировки.

Если stable 1.1 загрузила каталог sync-плагина на Диск, обычная migration
блокирует чтение этих данных. Force исключает собственные credentials
из source/archive и сохраняет защищённые remote plugin copies без их чтения.
Ранее раскрытые удалённые копии необходимо удалить отдельно.
Ранее раскрытый OAuth token следует заменить отдельно: Force не отменяет утечку.
Force remote не переносит plugin data; неоднозначные portable source paths
блокируются до local writes.

Encrypted legacy и все остальные исторические форматы не поддерживаются.
Невалидные локальные данные блокируют startup и mutating workflows. Неподдерживаемые
remote-форматы блокируют обычный sync; подтверждённый Force local может заменить
metadata назначения из читаемого local source без декодирования старого назначения. Нужно выбрать
чистый remote path либо вручную сбросить старые данные только после
самостоятельного backup. Текущие данные принимаются только с
semantic-маркерами `sync-index`, `encryption-manifest` и `plugin-data`;
converter/recovery для несовместимых исторических форматов нет.

Не запускайте старую версию плагина после перехода: она может заменить
canonical или вернуть удалённые файлы. Если это произошло, отключите синхронизацию
везде, выберите наиболее полную локальную копию, проверьте
backup/conflict-копии и повторите Force local с выбранным вариантом архива.

> **Сохранность данных**
> Для важных хранилищ нужен независимый backup. Удаления распространяются на
> другие устройства. Force заменяет выбранные файлы назначения с явным
> выбором backup. OAuth-токен и пароль шифрования хранятся открыто в локальных
> данных плагина; не передавайте эту директорию и диагностику с секретами.
> Плагин отправляет синхронизируемые данные на Яндекс Диск и не собирает телеметрию.
> Используйте его на свой риск; условия — в [LICENSE](LICENSE).

## Возможности

- **Реал-тайм синхронизация** — автоматическая загрузка изменённых файлов при сохранении
- **Периодическая полная синхронизация** — проверка и синхронизация всех файлов по таймеру
- **Двусторонняя синхронизация** — изменения с любого устройства синхронизируются на все остальные
- **Разрешение конфликтов** — причинные правила по SHA-256, server mtime и
  tombstone с сохранением вытесняемой локальной версии
- **Синхронизация удалений** — удалённые файлы удаляются на всех устройствах
- **Гибкие фильтры** — настраиваемые паттерны включения/исключения файлов
- **Поддержка нескольких устройств** — работа по одному токену на разных устройствах
- **Система бекапов** — создание ZIP-архивов хранилища на Яндекс Диске
- **Принудительная синхронизация** — подтверждённая замена выбранных файлов назначения данными с устройства или Диска
- **Сквозное шифрование** — AES-256-GCM для содержимого и детерминированный AES-SIV для имён с разделёнными ключами

## Установка

### Вручную

1. Скачайте `main.js`, `manifest.json` и `styles.css` из [последнего релиза](https://github.com/Ivansushkin/obsidian-yandex-disk-sync/releases)
2. Создайте папку `yandex-disk-sync` в `<Vault>/.obsidian/plugins/`
3. Скопируйте скачанные файлы в созданную папку
4. Перезапустите Obsidian
5. Включите плагин в **Настройки → Сторонние плагины**

### Через BRAT (для тестирования предварительных сборок)

1. Установите плагин [BRAT](https://github.com/TfTHacker/obsidian42-brat)
2. Добавьте репозиторий через BRAT
3. Выполните "Check for updates in BRAT"

## Настройка

### Получение OAuth-токена

1. Перейдите на [Яндекс OAuth](https://oauth.yandex.ru/)
2. Создайте приложение с правами на чтение и редактирование Яндекс Диска, а также «Доступ к папке приложения на Диске»

4. Вставьте токен в настройки плагина

## Использование

### Индикация синхронизации

Общая компактная плашка показывает `YD`, loader во время работы и значок состояния.
На desktop она справа снизу, на 8 px над status bar, вместо старого элемента YD
внутри бара. Нажатие раскрывает подробности вверх, повторное — сворачивает.
При скрытом status bar плашка остаётся над нижним краем окна. На Android,
iPhone и iPad она остаётся справа сверху, на 8 px ниже верхних элементов
и safe area; нажатие также раскрывает и сворачивает подробности.

Этап, известный прогресс, время последнего успеха и ошибка доступны только
при раскрытии. Длинный текст можно выделить и прокрутить. Обновления сохраняют
выбранный вид; ошибка не раскрывает плашку автоматически. Force, шифрование
и backup отражаются между внутренними этапами. Существующие уведомления
прогресса и блокировок сохранены. Покой не гарантирует, что отложенные изменения
или изменения на другом устройстве уже синхронизированы.

### Первый запуск

При первом запуске плагин проверяет наличие файлов локально и на Яндекс Диске:

- **Если локальное хранилище пусто, а на диске есть файлы** — файлы будут скачаны
- **Если диск пуст, а локально есть файлы** — файлы будут загружены
- **При подключении нового устройства к существующим облачным данным** — сначала применяются облачные версии. Отличающиеся локальные версии сохраняются в `.obsidian/plugins/yandex-disk-sync/overwritten/`. Облачные удаления применяются с защитными копиями; файлы только на устройстве сохраняются и загружаются после начального получения. Последующая синхронизация работает по обычным двусторонним правилам.

> **Рекомендация**
> Перед первой синхронизацией создайте ручной бекап вашего хранилища. При работе с облачными данными всегда есть риск потери информации.

### Работа на нескольких устройствах

1. Настройте плагин на первом устройстве и выполните первичную синхронизацию
2. На втором устройстве установите плагин с тем же токеном и путём
3. Плагин автоматически скачает файлы с Яндекс Диска

> **Важно**
> Используйте один и тот же токен на всех устройствах. При смене токена потребуется перенастроить синхронизацию на всех устройствах.

### Разрешение конфликтов

Локальные изменения определяются по SHA-256, удалённые — по server mtime и
серверному fingerprint. Если изменились обе стороны, плагин создаёт
conflict-копию. Последовательные изменения одного installation ID остаются
причинными даже во время незавершённого upload и не создают conflict-копий.
Точечное удаление побеждает конкурентное изменение, но
вытесняемое локальное содержимое сначала сохраняется в backup. Новый или
изменённый файл внутри конкурентно удалённой папки выживает.

> **Предупреждение**
> Удаления распространяются на все устройства. Для важных vault храните
> независимый backup, особенно перед Force sync.

### Система бекапов

Плагин включает встроенную систему бекапов для создания ZIP-архивов вашего хранилища:

- **Создание бекапов**: Настройки плагина → Секция "Бекап" → Кнопка "Сделать бекап"
- **Место хранения**: Бекапы сохраняются в папку `.backup` на Яндекс Диске
- **Формат**:
  `backup_YYYY-MM-DD_HH-MM-SS-SSS_<96-bit-random>[.enc].zip`
- **Encrypted backup**: самодостаточный аутентифицированный envelope; при
  скачивании сохраняется обычный `.zip`, а UI может запросить пароль архива
- **Содержимое**: Все файлы, подлежащие синхронизации согласно фильтрам
- **Доступность**: Каждое устройство читает общий список бекапов напрямую из
  защищённой удалённой папки `.backup`

**Примечание**: Папка `.backup` защищена и исключена из операций синхронизации.

### Принудительная синхронизация

Force заменяет выбранные файлы назначения фактическим источником напрямую.
В обоих направлениях учитываются включения, исключения, защищённые пути и
настройка синхронизации конфигурации Obsidian.

- **Локальное → Диск:** заменить выбранные файлы и пересоздать index.
  Для зашифрованного назначения нужен проверенный пароль: иначе нельзя отличить
  выбранные пути от исключений. При сохранении шифрования его параметры сохраняются.
- **Диск → локальное:** прочитать и расшифровать выбранный physical source,
  заменить выбранные локальные файлы. Исключения, .backup и этот плагин сохраняются.

Force не отключает шифрование, если это оставит исключённые зашифрованные файлы
без ключа: сначала используйте настройки шифрования. Повреждённый manifest
назначения и конфликт файла с папкой исключений блокируют замену до записи.

Источник должен успешно читаться. Пустая прочитанная выборка очищает только выбранные файлы назначения.
Временные файлы, locks, trash и защитные/conflict copies Force не создаёт.
Одно подтверждение показывает исключения и необязательный архив, выключенный по
умолчанию. Ошибка архива остаётся в том же диалоге до retry/отключения/отмены.
После замены конфигурации перезапустите Obsidian.

Ошибки отдельных действий не останавливают остальные. Частичный результат содержит
ошибки; обычный manual/startup/scheduled full повторяет остаток без повторной
полной очистки. Новый Force всегда начинает новую подтверждённую замену.
Остановка других устройств не обязательна; защита от их поздних запросов не
гарантируется. Подробнее: [контракт Force](docs/FORCE_SYNC.md).

## Шифрование

Новые encrypted vault используют профиль `hardened`: PBKDF2-HMAC-SHA256 с
600 000 итераций выводит master key, после чего HKDF-SHA256 создаёт независимые
ключи AES-256-GCM для содержимого и AES-SIV для имён.

Включение, выключение и смена пароля берут **локальные файлы запускающего
устройства как эталон** в текущих фильтрах синхронизации. Remote-only файлы и
старые offline-правки других устройств не добавляются к этому эталону. После
перехода другие устройства автоматически получают выбранную версию; их прежние
очереди и выбранные локальные extras заменяются.

До завершения не редактируйте vault ни на одном устройстве. Уже отправленные
чужие запросы могут завершиться позже проверки: server fencing отсутствует.
Каждый новый target проходит read-back с проверкой plaintext SHA-256. При сбое
сохраняется recovery; возможность завершения другим устройством и ограничения
старых checkpoints описаны в [документации шифрования](docs/E2E_ENCRYPTION.md).
Пароль нового устройства сохраняется только после verifier и чтения canonical;
неверный пароль и отмена не заменяют активные settings.

- **Шифрование содержимого**: каждый файл получает случайный 12-байтный IV, что гарантирует уникальный шифротекст даже для одинаковых файлов
- **Шифрование имён**: RFC 5297 AES-SIV с постоянным domain AAD и canonical Base64URL; имена стабильны между устройствами, а move папки не перекодирует потомков
- **Ключ**: выводится из вашего пароля + случайной 16-байтной соли — мастер-ключ никогда не покидает ваше устройство
- **Несколько устройств**: соль хранится в общем файле `.obsidian-encrypt.json` на Яндекс Диске (raw, без шифрования). При включении шифрования на новом устройстве плагин автоматически определяет зашифрованные данные, запрашивает пароль и проверяет его корректность

**Как включить**:

1. Перейдите в **Настройки → Секция "Шифрование"**
2. Нажмите на тоггл шифрования
3. Введите и подтвердите пароль
4. Выберите полный архив, продолжение без него или отмену. Выбранный архив проходит побайтовую проверку
5. Не меняйте файлы на устройствах до завершения перехода; выбранные локальные файлы будут загружены в зашифрованном виде

**Восстановление пароля**: Пароль НЕ восстанавливается. Если вы потеряете пароль при включённом шифровании, ваши данные на Яндекс Диске станут навсегда недоступны. Храните пароль в надёжном месте (например, в менеджере паролей).

**Хранение пароля**: Пароль хранится в `data.json` (конфиг плагина Obsidian) в открытом виде. Он никогда не отправляется на Яндекс или третьим лицам.

> **Предупреждение**
> Переход заменяет выбранную область Диска локальным эталоном. До commit
> авторитетен исходный режим, после commit — новый; rollback после commit
> запрещён. Protected/excluded paths сохраняются. Заранее сохраните нужные
> remote-only и offline-правки отдельно. Полученные encrypted данные требуют пароля.

Numeric historical manifest и исторические encrypted backup-форматы не
поддерживаются. Non-envelope `.enc.zip`, encrypted legacy names и historical `.zip` без
plaintext ZIP magic отклоняются без попытки compatibility decrypt. Старые
plaintext ZIP по-прежнему можно скачать.

## Разработка

Нужны Node.js 20.19+ и npm.

```bash
npm install
npm test
npm run lint
npm run build
npm run format:check
```

Сборка создаёт release assets в `build/`; `npm run dev` включает incremental build.
Настройка тестового vault через `.env`, hooks, форматирование и диагностика описаны
в [руководстве разработки](docs/README.md#разработка-и-проверки).
[AGENTS.md](AGENTS.md) задаёт правила кода и компактных algorithm tests.
Реальная проверка Obsidian выполняется по [smoke-сценариям](docs/SMOKE_TESTS.md).

## Безопасность

- OAuth-токен хранится в открытом виде в локальных данных плагина, поскольку у
  мобильных плагинов Obsidian нет переносимого доступа к системному хранилищу ключей
- Токен не логируется и не передаётся третьим лицам
- Выдавайте только OAuth-права, необходимые для чтения и записи выбранного хранилища
- Удаление локальных данных плагина не отзывает OAuth-токен; отзывайте ненужные токены через Яндекс OAuth
- Все сетевые запросы используют HTTPS с проверкой сертификатов
- Данные пользователя никогда не собираются и не анализируются разработчиком плагина
- **Сквозное шифрование**: содержимое использует AES-256-GCM, имена — AES-SIV; производные ключи остаются в памяти устройства

## Ограничения

- Обычный sync не переносит пустые папки; direct Force переносит их. Симлинки и специальные атрибуты файлов не синхронизируются.
- Старые и текущие версии плагина нельзя одновременно подключать к одному remote-хранилищу.
- Квоты, размер файлов и throttling задаёт Яндекс Диск; проверяйте ограничения своего
  аккаунта. Плагин не может их увеличить.
- Создание ZIP удерживает файлы архива в памяти. Realtime-окна сокращают retained
  content, но не задают hard cap памяти устройства или размера одиночного файла.
- При сетевом отказе durable work остаётся для recovery; покой плашки не доказывает
  схождение всех устройств. Реальные desktop/mobile проверки выполняются отдельно
  от автоматических тестов.
