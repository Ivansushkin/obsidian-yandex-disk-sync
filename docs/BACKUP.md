# Система резервного копирования

## Обзор

Плагин Yandex Disk Sync включает встроенную систему резервного копирования, которая позволяет создавать ZIP-архивы хранилища и сохранять их на Яндекс.Диске в защищенной папке `.backup`.

## Основные возможности

- **Создание ZIP-архивов** всех синхронизируемых файлов по команде пользователя
- **Сохранение на Яндекс.Диск** в изолированной папке `.backup`
- **Общий список на всех устройствах** — список читается непосредственно из
  удалённой папки `.backup`
- **Доступ ко всем бекапам** с любого устройства через список в настройках
- **Скачивание бекапов** на локальное устройство для внешней архивации
- **Защита от случайного удаления** - папка `.backup` исключена из всех операций синхронизации

## Формат бекапа

Бекапы сохраняются в формате ZIP с именем:

```
backup_YYYY-MM-DD_HH-MM-SS.zip
backup_YYYY-MM-DD_HH-MM-SS.enc.zip
```

Суффикс `.enc.zip` означает, что архив был загружен через активный encryption
codec. Для его чтения нужен тот же ключ, с которым создавался backup.

## Структура архива

ZIP-архив содержит все файлы, которые подлежат синхронизации согласно текущим настройкам фильтров (include/exclude patterns). Структура файлов в архиве соответствует структуре хранилища Obsidian.

## Расположение бекапов

Бекапы сохраняются в папке `.backup` внутри целевой папки синхронизации на Яндекс.Диске:

```
{your-remote-path}/.backup/
├── backup_2026-01-18_15-30-45.zip
├── backup_2026-01-19_10-15-30.zip
└── ...
```

## Использование

### Создание бекапа

1. Откройте настройки плагина
2. Перейдите в секцию "Backup"
3. Нажмите кнопку "Create backup"
4. Дождитесь завершения операции

### Просмотр всех доступных бекапов

1. Откройте настройки плагина
2. Перейдите в секцию "Backup"
3. Нажмите кнопку "Show all backups"
4. В открывшемся окне будет отображен список всех доступных бекапов с датой создания и размером

### Скачивание бекапа

1. Откройте список всех бекапов (см. выше)
2. Нажмите кнопку "Download" рядом с нужным бекапом
3. Файл будет скачан на локальное устройство

### Просмотр последнего бекапа

В секции "Backup" отображается время самого нового файла из текущего remote
listing либо сообщение "Never", если папка `.backup` пуста.

## Синхронизация между устройствами

Backup metadata не записывается в canonical index. Каждое устройство получает
актуальный список напрямую из `.backup`, поэтому архив, созданный одним
устройством, доступен остальным без отдельного index commit.

## Защита данных

### Исключение из синхронизации

Папка `.backup` жестко исключена из всех операций синхронизации:

- Не скачивается при начальной синхронизации
- Не удаляется при очистке или конфликтах
- Не индексируется при построении списка файлов

### Техническая защита

Защита реализована на нескольких уровнях:

1. **path-utils.ts**: Функция `isProtectedPath()` проверяет защищенные пути
2. **shouldSyncFile()**: Возвращает `false` для файлов в `.backup`
3. **IndexManager**: Фильтрует `.backup` при получении списка удаленных файлов

## Техническая реализация

### Основные компоненты

- **BackupManager**: Управляет созданием, загрузкой и скачиванием бекапов
- **BackupListModal**: UI компонент для отображения списка бекапов
- **Settings UI**: Предоставляет интерфейс для создания бекапов и просмотра списка

### API методы

```typescript
// Создание бекапа
await plugin.createBackup(): Promise<{success: boolean, backupName?: string, error?: string}>

// Получение менеджера бекапов
plugin.getBackupManager(): BackupManager

// Получить список всех бекапов
await backupManager.listBackups(): Promise<BackupInfo[]>

// Скачать конкретный бекап
await backupManager.downloadBackup(backupPath): Promise<ArrayBuffer>
```

### Формат данных

Информация о бекапах хранится только на Яндекс.Диске в папке `.backup`:

- файлы архивов в формате `.zip` или `.enc.zip`;
- имя, размер и время берутся из remote listing;
- canonical index не содержит backup timestamps или список архивов.

## Ограничения

- Бекапы создаются только из синхронизируемых файлов (с учетом фильтров)
- Максимальный размер архива ограничен возможностями Яндекс.Диска
- Время создания бекапа зависит от количества файлов и скорости интернета
- После rotate старый `.enc.zip` может потребовать прежний пароль/ключ; новый
  ключ не используется для автоматического перешифрования существующих архивов

## Рекомендации

1. **Регулярное создание бекапов** перед важными изменениями
2. **Проверка доступного места** на Яндекс.Диске
3. **Хранение нескольких копий** для дополнительной безопасности
4. **Мониторинг уведомлений** о успешном создании бекапа
5. **Скачивание бекапов** на локальное устройство для внешней архивации

## Устранение неполадок

### Бекап не создается

- Проверьте подключение к Яндекс.Диску (используйте кнопку "Test")
- Убедитесь, что есть синхронизируемые файлы
- Проверьте доступное место на диске

### Бекап поврежден

- Повторите создание бекапа
- Проверьте целостность файлов хранилища перед бекапом

### Новый backup не появился на другом устройстве

- Повторно откройте список backup, чтобы обновить remote listing
- Проверьте доступ к папке `.backup`; full sync и canonical index для этого не нужны
