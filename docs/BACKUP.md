# Система резервного копирования

## Обзор

Плагин Yandex Disk Sync включает встроенную систему резервного копирования, которая позволяет создавать ZIP-архивы хранилища и сохранять их на Яндекс.Диске в защищенной папке `.backup`.

## Основные возможности

- **Автоматическое создание ZIP-архивов** всех синхронизируемых файлов
- **Сохранение на Яндекс.Диск** в изолированной папке `.backup`
- **Синхронизация между устройствами** - время последнего бекапа отображается на всех устройствах
- **Защита от случайного удаления** - папка `.backup` исключена из всех операций синхронизации

## Формат бекапа

Бекапы сохраняются в формате ZIP с именем:
```
backup_YYYY-MM-DD_HH-MM-SS.zip
```

Например: `backup_2026-01-18_15-30-45.zip`

## Структура архива

ZIP-архив содержит все файлы, которые подлежат синхронизации согласно текущим настройкам фильтров (include/exclude patterns). Структура файлов в архиве соответствует структуре хранилища Obsidian.

## Расположение бекапов

Бекапы сохраняются в папке `.backup` внутри целевой папки синхронизации на Яндекс.Диске:

```
{your-remote-path}/.backup/
├── backup_2026-01-18_15-30-45.zip
├── backup_2026-01-19_10-15-30.zip
└── ...
```

## Использование

### Создание бекапа

1. Откройте настройки плагина
2. Перейдите в секцию "Backup"
3. Нажмите кнопку "Create backup"
4. Дождитесь завершения операции

### Просмотр последнего бекапа

В секции "Backup" отображается время последнего успешно созданного бекапа или сообщение "Never" если бекапы еще не создавались.

## Синхронизация между устройствами

Время последнего бекапа синхронизируется между всеми устройствами через файл индекса синхронизации (`.obsidian-sync-index.json`). Это означает:

- Создание бекапа на одном устройстве обновит информацию о последнем бекапе на всех других устройствах
- Все устройства показывают одинаковое время последнего бекапа

## Защита данных

### Исключение из синхронизации

Папка `.backup` жестко исключена из всех операций синхронизации:
- Не скачивается при начальной синхронизации
- Не удаляется при очистке или конфликтах
- Не индексируется при построении списка файлов

### Техническая защита

Защита реализована на нескольких уровнях:
1. **path-utils.ts**: Функция `isProtectedPath()` проверяет защищенные пути
2. **shouldSyncFile()**: Возвращает `false` для файлов в `.backup`
3. **IndexManager**: Фильтрует `.backup` при получении списка удаленных файлов

## Техническая реализация

### Основные компоненты

- **BackupManager**: Управляет созданием и загрузкой бекапов
- **IndexManager**: Хранит время последнего бекапа в синхронизируемом индексе
- **Settings UI**: Предоставляет интерфейс для создания бекапов

### API методы

```typescript
// Создание бекапа
await plugin.createBackup(): Promise<{success: boolean, backupName?: string, error?: string}>

// Получение времени последнего бекапа
plugin.getLastBackupTime(): number | null
```

### Формат данных

Время последнего бекапа хранится в `SyncIndex`:

```typescript
interface SyncIndex {
    // ... другие поля
    lastBackupTime?: number; // Timestamp последнего бекапа
}
```

## Ограничения

- Бекапы создаются только из синхронизируемых файлов (с учетом фильтров)
- Максимальный размер архива ограничен возможностями Яндекс.Диска
- Время создания бекапа зависит от количества файлов и скорости интернета

## Рекомендации

1. **Регулярное создание бекапов** перед важными изменениями
2. **Проверка доступного места** на Яндекс.Диске
3. **Хранение нескольких копий** для дополнительной безопасности
4. **Мониторинг уведомлений** о успешном создании бекапа

## Устранение неполадок

### Бекап не создается

- Проверьте подключение к Яндекс.Диску (используйте кнопку "Test")
- Убедитесь, что есть синхронизируемые файлы
- Проверьте доступное место на диске

### Бекап поврежден

- Повторите создание бекапа
- Проверьте целостность файлов хранилища перед бекапом

### Время бекапа не синхронизируется

- Выполните полную синхронизацию
- Проверьте, что файл `.obsidian-sync-index.json` успешно загружается
